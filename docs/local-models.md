# Локальные модели для RAG: выбор и настройка под 6 ГБ ОЗУ

Все компоненты системы работают **полностью локально**: документы, векторная база,
эмбеддинги, генерация ответов, Excel-журнал расходов. Наружу уходят только запросы
к Telegram API (и то через прокси, если он настроен).

## Итоговая конфигурация (6 ГБ ОЗУ)

| Компонент | Модель | Размер | ОЗУ в работе | Почему |
|---|---|---|---|---|
| Эмбеддинги (векторизация) | `intfloat/multilingual-e5-small` | ~0,5 ГБ | ~0,6 ГБ | Оптимум качество/скорость/память для CPU (см. ниже) |
| Генерация (RAG-ответы) | `qwen2.5:1.5b-instruct-q4_K_M` (Ollama) | ~1 ГБ | ~1,5–2 ГБ | Лучший русский в классе 1–2B, ловит JSON-режим |
| Векторная база | SQLite (в проекте) / pgvector | — | ~0,3 ГБ | 153 чанка + 76 показателей — Brute-force косинус мгновенный |
| Реранкер | `heuristic` (код) | 0 | ~0 | Без доп. вызовов LLM — экономия секунд на каждом вопросе |
| Верификатор чисел | код (`app/agents.py`) | 0 | ~0 | Гарантия grounded-ответов без LLM |

Итого пик: **~3 ГБ ОЗУ** на модели + ~1 ГБ на Python/бота = комфортно в 6 ГБ,
остаётся запас на ОС и браузер.

## Бюджет памяти (почему именно так)

```
6 ГБ ОЗУ
├─ Windows + базовые процессы      ~2,0 ГБ
├─ Python-бот (aiogram, SQLAlchemy, pandas) ~0,7 ГБ
├─ Ollama + Qwen2.5-1.5B q4_K_M    ~1,5–2,0 ГБ (держится в памяти между вопросами)
├─ e5-small (sentence-transformers)  ~0,6 ГБ (загружается лениво, один раз)
└─ запас                            ~1 ГБ
```

Правило: **эмбеддинг-модель + LLM вместе не должны превышать ~3 ГБ**. Модели
больше (bge-m3 2,3 ГБ + Qwen 3B 2 ГБ) уже не влезают вместе с ОС.

## 1. Эмбеддинги: `intfloat/multilingual-e5-small`

Сравнение кандидатов для русского языка (MIRACL ru-бенчмарк, качество ретрива):

| Модель | Файл | dim | Скорость CPU* | Качество рус. |
|---|---|---|---|---|
| hash (провайдер) | 0 | 768 | мгновенно | низкое (только слова) |
| paraphrase-multilingual-MiniLM-L12-v2 | 0,5 ГБ | 384 | ~30 мс/чанк | среднее |
| **multilingual-e5-small** | **0,5 ГБ** | **384** | **~40 мс/чанк** | **высокое** |
| multilingual-e5-base | 1,1 ГБ | 768 | ~90 мс/чанк | чуть выше e5-small |
| multilingual-e5-large | 2,2 ГБ | 1024 | ~250 мс/чанк | очень высокое |
| BAAI/bge-m3 | 2,3 ГБ | 1024 | ~500 мс/чанк | максимальное |

\* ориентиры на 4-ядерном CPU; на GTX 1050 Ti (fp16) — в ~10 раз быстрее.

Выбор e5-small: тот же размер, что MiniLM, но заметно лучше на русском
(обучена с contrastive-целью на 100+ языках, mE5-семейство держит топ MIRACL/ruMTEB).
Отчёт из 40 чанков векторизуется ~2 с на CPU — приемлемо для Telegram-бота.
В системе уже есть гибридный поиск (BM25 + RRF), который компенсирует
разрыв с bge-m3 по качеству плотного поиска.

**Настройка** (уже в `.env`):

```env
EMBEDDINGS_PROVIDER=sentence_transformers
EMBEDDINGS_LOCAL_MODEL=intfloat/multilingual-e5-small
EMBEDDINGS_DIM=384
```

Кэш моделей — в `hf-cache/` рядом с проектом (HF_HOME задаёт start.bat).
После смены модели обязательна переиндексация: `venv\Scripts\python.exe -m scripts.reindex`.

## 2. Генерация: `qwen2.5:1.5b-instruct-q4_K_M` через Ollama

Кандидаты на роль локальной LLM (8–16 ГБ не рассматриваем — не влезает):

| Модель | Файл | Русский | JSON-режим | Комментарий |
|---|---|---|---|---|
| llama3.2:1b | 1,3 ГБ | слабый | плохо | англо-центричная |
| gemma2:2b | 1,6 ГБ | средний | средне | хорошая, но рус. слабее Qwen |
| **qwen2.5:1.5b** | **1,0 ГБ** | **хороший** | **надёжно** | мультиязычная цель обучения |
| qwen2.5:3b | 1,9 ГБ | хороший+ | надёжно | вариант на 12+ ГБ ОЗУ |
| vikhr/qwen и пр. | ~1,5 ГБ | хороший | — | есть, но официальная стабильнее |

Квантизация **q4_K_M** — стандартный баланс: почти качество q8 при вдвое
меньшем файле. Замеры на этой машине (CPU):

- классификация запроса (JSON, 300 токенов): **1,5–2,5 с**
- ответ-композитор (450 токенов): **0,9–1,5 с**
- итоговая латентность вопроса: **~3–5 с** (плюс поиск) — нормально для Telegram.

**Настройка** (уже в `.env`):

```env
LLM_PROVIDER=openai_compatible
LLM_API_BASE=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5:1.5b-instruct-q4_K_M
LLM_TIMEOUT_S=180
RERANKER=heuristic          # без доп. вызовов слабой LLM
ANONYMIZE_PROMPTS=false     # данные не покидают машину — маскировка не нужна
```

Установка Ollama: https://ollama.com/download → `ollama pull qwen2.5:1.5b-instruct-q4_K_M`.

### Если скачивание модели падает (блокировка R2 хранилища)

Blob-хранилище Ollama (`*.r2.cloudflarestorage.com`) у некоторых провайдеров
недоступно напрямую, а через HTTP-прокси ломается TLS. Симптом:
`http: server gave HTTP response to HTTPS client`. Решение — качать через
socks5-прокси (клиент должен быть запущен):

```powershell
$env:HTTPS_PROXY='socks5://127.0.0.1:7897'   # порт вашего прокси-клиента
ollama pull qwen2.5:1.5b-instruct-q4_K_M
```

Альтернатива без прокси — скачать GGUF с HuggingFace и импортировать:
https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF (HF доступен напрямую).

### Важный нюанс Windows: системный прокси и localhost

`httpx` (клиент приложения) с настройками по умолчанию читает **системный прокси
Windows из реестра** — и запросы к `http://localhost:11434` молча уходят в прокси
и виснут. Приложение это обходит автоматически (`app/llm.py` включает
`trust_env=False` для локальных адресов) — но имейте в виду при своих скриптах.

### Если Ollama падает с «CUDA error» / «failure during GPU discovery»

Симптом: `/api/tags` отвечает, но любой запрос к модели возвращает 500 с
`llama runner process has terminated: CUDA error`, а в `%LOCALAPPDATA%\Ollama\server.log`
видно `failure during GPU discovery ... failed to finish discovery before timeout`.
Это несовместимость CUDA-рантайма Ollama с драйвером/видеокартой, а не проблема
проекта: `scripts/check_env.py` покажет это как `[СТОП] LLM API недоступен (LLM API 500)`.

Быстрое решение — считать на CPU (для модели 1,5B потеря скорости небольшая):

```powershell
# остановить сервис и поднять его без GPU
Get-Process ollama* | Stop-Process -Force
$env:OLLAMA_LLM_LIBRARY = "cpu"
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" serve
```

Чтобы не повторять каждый раз, задайте переменную на уровне пользователя
(действует после перезапуска Ollama и не влияет на другие модели, запускаемые
вручную из другого окна):

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_LLM_LIBRARY", "cpu", "User")
```

Если GPU нужен для других задач, вместо этого обновите драйвер NVIDIA либо
поставьте Ollama версии с подходящим CUDA-рантаймом — переменную тогда
использовать не нужно.

## 3. Реранкер и верификатор

- `RERANKER=heuristic` — локальные эвристики (перекрытие токенов + фраза +
  семантика). На маленькой LLM каждый реранк-вызов — это +2–4 с latency и
  низкое качество оценок, поэтому LLM-реранкер выключен. Гибридный поиск
  (BM25 + векторы + RRF) уже даёт хорошее ранжирование.
- `VERIFY_ANSWERS=true` — верификатор **не использует LLM**: извлекает числа из
  ответа и сверяет их с блоком ДАННЫЕ (значения payload) и с шаблоном,
  собранным из тех же данных, с учётом единиц и валюты. Отдельно проверяется,
  что число отнесено к тому периоду, к которому относится. Постороннее число
  или перепутанный период → повтор генерации → шаблонный ответ. Это бесплатная
  защита от галлюцинаций Qwen.

## 4. Если памяти станет больше (12–16 ГБ)

1. Эмбеддинги → `BAAI/bge-m3` (dim 1024) + `python -m scripts.reindex`
2. LLM → `ollama pull qwen2.5:3b-instruct-q4_K_M`, `LLM_MODEL=qwen2.5:3b-instruct-q4_K_M`
3. `RERANKER=crossencoder` + `RERANK_MODEL=BAAI/bge-reranker-base` (локальный кросс-энкодер)

## 5. Расходы «на лету» и Excel-журнал

Сообщения вида «расход: 1500 кофе» / «доход: 50000 зарплата» бот разбирает
локально (регулярка, без LLM — мгновенно) и пишет сразу в три места:

1. **Excel-журнал** `data/расходы.xlsx` — колонки Дата/Тип/Сумма/Категория/Описание;
   файл лежит локально, открывается Excel/LibreOffice; `/ledger` присылает копию
   и печатает сводку месяца по категориям;
2. **`ledger_operations`** в БД — построчные операции (кнопка «операции за месяц»);
3. **Факт месяца** по показателю «личные расходы»/«личные доходы» — поэтому
   работают вопросы «сколько я потратил в этом месяце?», сравнения и прогноз.

Категория определяется по описанию (`app/categories.py`: Кафе, Транспорт,
Продукты, …). Дата — сегодняшняя, можно задать явно: «расход: 300 обед (03.01)».
`/undo` отменяет последнюю запись (БД + Excel пересчитываются).
